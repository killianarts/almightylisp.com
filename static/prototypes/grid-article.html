To LOOP or not to LOOP

loop is a small language with its own grammar, built into Common Lisp. Some programmers write every iteration with it and some refuse to. The better question is which loops it makes clearer, and which it makes worse.

1

A language inside the language

Almost every form in Common Lisp is a list you can read from the inside out. loop isn't. Its arguments are a run of clauses that read almost like English, :for x :in list :collect x, and the macro parses them with a grammar of its own, set out in section 6.1 of the standard.

None of that costs anything when the program runs. Expand a loop and you get ordinary Lisp: a block, a let for the variables, and a tagbody that jumps back to the top with go. The cost is paid by whoever reads the code, and whether it's worth paying depends on the loop.

Syntax

loop [name-clause] {variable-clause}* {main-clause}* => result*

Try it

Put the cursor on any loop form and press C-c C-m in Sly to see it expanded one step.

Keywords or symbols

loop matches clause names by their spelling, so :for and for mean the same thing. This magazine writes them as keywords so they stand apart from your variables.

On SBCL, loop updates a single variable on every pass instead of binding a new one, so all three closures share it and see its last value. The same code written with dolist returns (1 2 3) on SBCL, and a mapcar always does, because each call to the function gets its own binding. To capture the variable inside loop, rebind it: (let ((x x)) (lambda () x)).

Syntax

:when form clause {:and clause}* [:else clause {:and clause}*] [:end]

The standard

Whether dolist makes a new binding on each pass is left to the implementation. Portable code shouldn't count on either behaviour, in dolist or in loop.

4

The alternatives

When loop is the wrong tool, it's usually because a simpler one says the same thing in fewer words. For one transformation, one filter or one total, the sequence functions read better, because their names state the intent:

For side effects with no result, dolist and dotimes are shorter and say so. And if you want everything loop does with Lisp's own syntax, there's ITERATE, a library on Quicklisp. Each clause is a form in parentheses, so a when has a body you can see:

The trap from the last section can't happen here. Both clauses are inside the when because the parentheses put them there, and your editor can move, wrap or delete each one as a unit. The price is a dependency, and one more library every reader of your code has to know.

Syntax

reduce function sequence &key key from-end start end initial-value => result

Getting ITERATE

Load it with (ql:quickload "iterate"), then define your package with (:use :cl :iterate), as the grades package here does.

5

A rule you can use

Ask what the loop produces, then pick the smallest tool that says it.

If the loopUse
changes every elementmapcar, map
keeps some elementsremove-if-not
boils everything down to one valuereduce, count-if, every, some
only has side effectsdolist, dotimes
gathers several results in one pass, or walks two sequences in steploop
needs a condition around several clausesloop with :and, or ITERATE

The last two rows are where loop is worth its grammar. Everywhere else it's a longer way of saying something Common Lisp already has a word for.

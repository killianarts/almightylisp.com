1

The signal is not the end

A signal in Common Lisp does not mean the process is over. error enters the debugger with the stack that was running, and the debugger lists restarts: named ways back into the program that the code, or the implementation, prepared in advance.

The useful question is which restart puts the program back on the path you wanted, not how fast you can kill the image and start another one.

In the book

Errors and Conditions walks through conditions, handlers, and restarts with the same stack still alive.

2

Pick a restart, then continue

A handler can print a warning and invoke a restart that supplies a replacement value. The function that signalled returns that value to its caller, and the caller keeps going. The bug is still worth fixing. The process does not have to die for you to see the next line run.

Compile the fixed function into the same image, then run the call again. The restart you chose was a way through the bad case. The new definition is how the bad case stops happening.
